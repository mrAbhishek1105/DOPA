# Preamble

# Part I — Domain Model Hierarchy

## §1. The Five Canonical Artifacts

Every operation in DOPA transforms one of these artifacts into the next. Nothing bypasses them. No component may produce or consume an artifact outside this chain.

```
┌─────────────────────────────────────────────────────────────────────┐
│                    DOPA ARTIFACT PIPELINE                           │
│                                                                     │
│  Requirement ──► ArchitectureIntent ──► LogicalArchitecture         │
│       │                                                             │
│       └──► ArchitectureGraph ──► InfrastructureArtifact             │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.1 Requirement

A structured, validated set of user needs expressed in domain terms. This is the **input contract** — the only artifact that originates outside the system.

```python
class Requirement(BaseModel):
    """Structured user requirements — the system's input contract."""
    application_type: str                    # ecommerce, saas, streaming, etc.
    cloud: Literal["aws", "gcp", "azure"]    # provider preference
    traffic: str | int | None                # "low" | "medium" | "high" | numeric
    availability: str | None                 # "standard" | "high" | "multi_region"
    region: str | None                       # AWS region code or alias
    budget: str | None                       # "low" | "medium" | "high"
    database: str | None                     # "sql" | "nosql"
    compliance: str | None                   # "soc2" | "hipaa" | "pci" | "gdpr"
    users: int | None                        # expected user count
    team_size: str | None                    # "small" | "medium" | "large"
    latency_sla: str | None                  # latency requirements
    media_storage: str | None                # "low" | "medium" | "high"
    realtime_latency: str | None             # "yes" | "no"
```

**Status:** ✅ EXISTS as `RequirementModel` in `backend/schemas/requirements.py`

### 1.2 ArchitectureIntent

A semantic interpretation of what the user *wants to achieve*. Multiple intents may be derived from a single Requirement. This is the **first transformation** — from raw data to architectural meaning.

```python
class ArchitectureIntent(BaseModel):
    """What the user wants to achieve — the semantic layer."""
    intent_id: str
    name: str                                 # "high_traffic_ecommerce", "real_time_chat"
    description: str
    confidence: float                         # 0.0 to 1.0
    trigger_fields: dict[str, Any]            # which requirement fields triggered this
    priority: int = 0                         # for conflict resolution
```

**Status:** ✅ EXISTS in `backend/schemas/architecture.py` but **NOT INTEGRATED** into the pipeline

### 1.3 LogicalArchitecture

A **cloud-agnostic** description of what services are needed, organized by logical component. This is the **second transformation** — from intent to abstract design.

```python
class LogicalComponent(BaseModel):
    """A cloud-agnostic logical building block."""
    component_id: str                         # "compute", "database", "cdn", "cache"
    label: str
    required: bool = True
    constraints: list[Constraint] = []

class ServiceCandidate(BaseModel):
    """A specific cloud service that fulfills a logical component."""
    service: str                              # "ecs", "rds", "cloudfront"
    provider: str                             # "aws", "gcp", "azure"
    score: float                              # 0.0 to 100.0
    best_for: list[str]
    avoid_when: list[str]
    selection_reason: str

class ComponentServiceMap(BaseModel):
    """Maps a logical component to its candidate services."""
    component_id: str
    component_label: str
    candidates: list[ServiceCandidate]
    selected: ServiceCandidate | None
    selection_policy: str                     # "cost_optimized" | "performance" | "balanced"

class LogicalArchitecture(BaseModel):
    """Cloud-agnostic architecture design."""
    architecture_id: str
    intents: list[ArchitectureIntent]
    components: list[ComponentServiceMap]
    style: ArchitectureStyle | None
    constraints: list[Constraint]
    reasoning_trace: list[dict]
```

**Status:** ⚠️ PARTIALLY EXISTS — `ArchitectureStyle`, `ComponentServiceMap`, `ServiceCandidate` are defined in `architecture.py` but `LogicalArchitecture` and `LogicalComponent` are missing. The current pipeline skips this layer entirely.

### 1.4 ArchitectureGraph

A **provider-specific** graph of nodes (services) and edges (relationships). This is the **third transformation** — from abstract design to concrete topology.

```python
class Node(BaseModel):
    id: str
    type: str                                 # "compute", "database", "cdn", "cache"
    provider: str                             # "aws"
    service: str                              # "ecs", "rds"
    metadata: dict

class Edge(BaseModel):
    id: str
    source: str
    target: str
    relationship: str                         # "routes_to", "stores_in", "triggers"
    properties: dict

class ArchitectureGraph(BaseModel):
    graph_id: str
    project_id: str
    version: str
    metadata: dict
    nodes: list[Node]
    edges: list[Edge]
```

**Status:** ✅ EXISTS as `ArchitectureGraph` in `backend/schemas/graph.py`

### 1.5 InfrastructureArtifact

A **deployable artifact** — Terraform, Pulumi, CloudFormation, Kubernetes manifests, or any other IaC format. This is the **fourth and final transformation** — from topology to deployable code.

```python
class InfrastructureArtifact(BaseModel):
    """A deployable infrastructure artifact."""
    artifact_id: str
    project_id: str
    graph_id: str
    provider: str                             # "terraform" | "pulumi" | "cloudformation"
    format: str                               # "hcl" | "yaml" | "json"
    content: str                              # the generated code
    metadata: dict
    validation: ArtifactValidation | None
```

### §3.1 Layer 1 — The Compiler (Core)

**Rules:**
- **100% deterministic** — same input always produces same output
- **Zero external dependencies** — no LLM calls, no API calls, no network I/O
- **Zero plugin awareness** — the compiler does not know about Terraform, Pulumi, or any deployment target
- **All knowledge is local** — knowledge files are bundled, versioned, and validated at startup
- **Engines are stateless** — all state is passed as parameters and returned in results

### §3.2 Layer 2 — Plugins

**Rules:**
- **Each plugin consumes exactly one artifact type** and produces exactly one artifact type
- **Plugins are swappable** — TerraformGenerator and PulumiGenerator both consume ArchitectureGraph and produce InfrastructureArtifact
- **Plugins are versioned** — each plugin declares its compatible compiler version
- **Plugins are discoverable** — registered via a plugin manifest, not hardcoded imports

**Defined Plugin Interfaces:**

```python
class ArtifactGenerator(ABC):
    """Consumes ArchitectureGraph, produces InfrastructureArtifact."""
    @abstractmethod
    def generate(self, graph: ArchitectureGraph) -> InfrastructureArtifact: ...

class SecurityAnalyzer(ABC):
    """Consumes ArchitectureGraph or InfrastructureArtifact, produces SecurityReport."""
    @abstractmethod
    def analyze(self, artifact: ArchitectureGraph | InfrastructureArtifact) -> SecurityReport: ...

class CostAnalyzer(ABC):
    """Consumes ArchitectureGraph, produces CostEstimate."""
    @abstractmethod
    def estimate(self, graph: ArchitectureGraph) -> CostEstimate: ...

class ComplianceEngine(ABC):
    """Consumes ArchitectureGraph + Requirement, produces ComplianceReport."""
    @abstractmethod
    def check(self, graph: ArchitectureGraph, requirement: Requirement) -> ComplianceReport: ...

class DiagramGenerator(ABC):
    """Consumes ArchitectureGraph, produces Diagram (SVG/PNG/HTML)."""
    @abstractmethod
    def render(self, graph: ArchitectureGraph) -> Diagram: ...

class ReportGenerator(ABC):
    """Consumes any artifact, produces a formatted report."""
    @abstractmethod
    def generate(self, artifacts: dict[str, Any]) -> Report: ...
```

**Current Plugin Status:** ❌ None implemented

**Rules:**
- **Platform components manage state, identity, and orchestration**
- **The platform does not contain business logic** — it delegates to the compiler and plugins
- **Thin Agents live here** — ephemeral, stateless workers (<150 lines) orchestrated by a kernel

# Part IV — Dependency Rules

## §5. Strict Dependency Direction

```
Layer 4 (Deployment) ──depends on──► Layer 3 (Platform)
Layer 3 (Platform)   ──depends on──► Layer 2 (Plugins)
Layer 2 (Plugins)    ──depends on──► Layer 1 (Compiler)
```

**Rule:** A layer may NEVER depend on a higher layer.
- A Plugin may NOT import Platform code
- The Compiler may NOT import Plugin code
- Deployment may NOT import Compiler code directly (must go through Plugin interface)

**Enforcement:** This is enforced by Python package structure:

```
backend/
├── compiler/          # Layer 1 — zero external deps
│   ├── engines/       # DiscoveryEngine, IntentEngine, etc.
│   ├── schemas/       # Domain models
│   └── knowledge/     # JSON knowledge files
├── plugins/           # Layer 2 — depends on compiler.schemas
│   ├── terraform/
│   ├── pulumi/
│   ├── security/
│   ├── cost/
│   └── compliance/
├── platform/          # Layer 3 — depends on compiler + plugins
│   ├── auth/
│   ├── projects/
│   ├── agents/
│   └── events/
└── deployment/        # Layer 4 — depends on platform
    ├── aws/
    ├── azure/
    └── devsecops/
```

# Part VI — Implementation Roadmap

## §7. Phased Build Order

### Phase 1: Complete the Compiler (Weeks 1-2)

**Goal:** Close the gap between Requirement and ArchitectureGraph by adding the missing engines.

1. **Create `IntentEngine`** — transforms `Requirement` → `list[ArchitectureIntent]`
   - Load `architecture-intents.json` (already exists in knowledge/)
   - Score intents by trigger field overlap
   - Return ranked, deduplicated intents

2. **Create `LogicalArchEngine`** — transforms `list[ArchitectureIntent]` → `LogicalArchitecture`
   - Load `architecture-styles.json` (already exists in knowledge/)
   - Map intents to logical components
   - Apply constraint resolution

3. **Create `ServiceSelector`** — transforms `LogicalArchitecture` → `ArchitectureOption`
   - Load `service-capabilities.json` (already exists)
   - Score each logical component's service candidates
   - Apply selection policy (cost/performance/balanced)

4. **Create `Pipeline`** — orchestrates the full compiler pipeline
   - `Requirement → IntentEngine → LogicalArchEngine → ServiceSelector → GraphEngine → GraphValidator`
   - Single entry point: `pipeline.run(requirement) → PipelineResult`

### Phase 2: Plugin System (Weeks 3-4)

**Goal:** Make the compiler extensible via plugins.

1. Define `PluginBase` abstract class
2. Create `PluginRegistry` — discovers and loads plugins
3. Implement `TerraformGenerator` as the first plugin
4. Implement `CostAnalyzer` as the second plugin

### Phase 3: Platform Foundation (Weeks 5-6)

**Goal:** Multi-tenant, stateful platform.

1. Refactor project CRUD into `platform/projects/`
2. Add artifact versioning and history
3. Add authentication and RBAC

### Phase 4: Deployment Targets (Weeks 7-8)

**Goal:** Generate deployable artifacts for at least one target.

1. Complete Terraform HCL generation
2. Add DevSecOps pipeline scaffolding
3. Add DPDP compliance plugin

# Part VII — Architectural Invariants

## §8. Rules That Cannot Be Broken

1. **The artifact pipeline is immutable.** No component may skip a stage. Requirement → Intent → LogicalArchitecture → Graph → Artifact. Always.

2. **Engines are deterministic.** Same input → same output. No randomness, no LLM calls, no network I/O.

3. **Plugins are swappable.** The compiler never imports a plugin directly. All plugin interaction is through abstract interfaces.

4. **Layers never look up.** Layer 1 never imports Layer 2. Layer 2 never imports Layer 3. Layer 3 never imports Layer 4.

5. **Knowledge is local.** All knowledge files are bundled with the compiler. No runtime API calls for pattern data.

6. **State is explicit.** No global state. No singletons. All state is passed as parameters and returned in results.

7. **The compiler has zero external dependencies.** No boto3, no terraform binary, no cloud SDKs. Those belong in plugins.
